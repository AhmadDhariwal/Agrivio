# 4. Implementation Planning Principles

The roadmap must:

* Follow frozen module ownership
* Preserve the modular monolith
* Implement foundational capabilities before dependent workflows
* Establish tenant isolation before tenant business modules
* Establish authentication and authorization before protected operations
* Establish transaction and idempotency infrastructure before financial workflows
* Implement authoritative movements before dashboards and reports
* Implement happy paths and failure paths together
* Include tests in every delivery item
* Avoid a separate “testing at the end” phase
* Avoid frontend-only feature completion without backend enforcement
* Avoid building all backend modules before any usable vertical slice
* Avoid client-specific forks
* Keep Release 1 scope frozen
* Use reversible, reviewable delivery increments

# 6. Release 1 Implementation Sequence

The roadmap must use the following ten delivery stages.

## F00 — Toolchain and Repository Bootstrap

Plan only; implementation begins after P1-07.

Cover:

* Monorepo initialization
* Angular application
* Express/TypeScript API
* Shared tooling configuration
* Package manager and workspace
* Build, lint, format, test, and type-check commands
* Local MongoDB replica-set topology
* Environment configuration validation
* Architecture-boundary testing foundation
* CI foundation

Exit gate:

* Empty applications build and test
* MongoDB transactions work locally
* Architecture checks can run
* No business feature implementation yet

## F01 — Platform Foundation

Cover:

* Configuration
* Request IDs
* Structured logs
* Central error handling
* Database connection
* Transaction abstraction
* Infrastructure-owned idempotency
* Health endpoint
* Audit foundation
* Shared API envelopes
* Decimal and date primitives
* Tenant-safe repository foundation

Exit gate:

* Infrastructure is testable
* No tenant repository can omit organization scope
* Transaction retry and idempotency tests pass

## F02 — Identity, Tenancy, and Subscription Access

Cover:

* Global users
* Memberships
* Opaque sessions
* CSRF
* Password reset
* Organization activation requests
* Initial Owner activation
* Active session context
* Permission evaluation
* Branch/warehouse assignment enforcement foundation
* Plans, subscription states, trial, grace, and suspension
* Manual billing evidence and Super Admin review

Exit gate:

* Organization onboarding works end-to-end
* Cross-tenant tests pass
* Subscription suspension blocks operational writes
* Platform and organization contexts remain separated

## F03 — Organization Setup and Master Data

Cover:

* Organization settings
* Branches
* Warehouses
* Employees and access assignments
* Categories
* Products
* Base units
* Packaging conversions
* Tracking modes
* Price tiers and prices
* Customers
* Suppliers
* Accounts
* Opening receivable/payable/account balances

Exit gate:

* A new approved organization can complete initial setup
* Opening financial entries reconcile
* Version conflicts are enforced
* Plan creation limits are enforced

## F04 — Inventory Engine

Cover:

* Product batches
* Opening stock
* Stock movements
* Inventory balances
* WAC cost states
* FEFO/FIFO allocation
* Expiry behaviour
* Negative-stock block and Owner override
* Stock adjustments and reversals
* Warehouse transfers and reversals
* Inventory reconciliation

Exit gate:

* Quantity and valuation reconciliation pass
* Concurrent stock posting cannot silently overwrite state
* Transfer failure cannot leave one-sided movement
* Batch identity remains preserved

## F05 — Purchases and Supplier Payables

Cover:

* Purchase drafts
* Purchase posting
* Batch and expiry receipt
* Landed-cost allocation
* WAC update
* Full, partial, and mixed purchase payment
* Supplier payable
* Supplier payments and advances
* Purchase cancellation
* Purchase returns
* Supplier ledger reconciliation

Exit gate:

* Purchase posts atomically
* Purchase failure rolls back all effects
* Supplier ledger and account movements reconcile
* Purchase returns enforce returnable and available quantity

## F06 — Sales, POS, and Customer Receivables

Cover:

* Sale drafts
* POS workflow
* Customer and walk-in handling
* Tier pricing
* Price override
* Unit conversion
* FEFO/FIFO allocation
* Cash, credit, partial, and mixed payments
* Branch invoice numbering
* Customer receivable
* Customer payment and advances
* Credit-limit approval
* Expired-stock approval
* Negative-stock override
* Sale cancellation
* Printing for 58 mm, 80 mm, and A4

Exit gate:

* Sale posts atomically
* Duplicate retries cannot duplicate invoices
* Stock, COGS, receivable, payment, and account effects reconcile
* Critical cashier workflow passes E2E tests

## F07 — Returns, Corrections, Accounts, and Expenses

Cover:

* Linked sales return
* Return without invoice
* Purchase return integration
* Sellable and unsellable stock
* Refund and ledger adjustment
* Return reversal
* Manual account inflow and outflow
* Account transfer
* Account transaction reversal
* Expenses and correction
* Shared corrective workflow validation

Exit gate:

* Every reversal nets against its source
* No generic arbitrary correction endpoint exists
* Return limits and batch availability are enforced
* Account balances reconcile to signed movements

## F08 — Alerts, Reporting, Imports, and Operational Views

Cover:

* Low stock
* Upcoming expiry
* Expired stock
* Dead stock
* Customer and supplier dues
* Dashboard
* Fixed reports
* Gross profit
* Inventory valuation
* PDF, Excel, and CSV exports
* Excel import preview and execution
* Audit views
* Backup and restore status views

Exit gate:

* Reports reconcile to authoritative effects
* Imports are all-or-nothing
* Alerts do not own conflicting balances
* Suspended read/export policy is enforced

## F09 — Hardening, Pilot, and Release

Cover:

* Full regression suite
* Security review
* Tenant-isolation attack tests
* Permission-matrix verification
* Performance baselines
* Accessibility checks
* Backup and restore rehearsal
* Import and migration rehearsal
* Pilot onboarding for initial clients
* UAT
* Defect stabilization
* Production readiness
* Release and rollback procedure

Exit gate:

* All release gates pass
* No unresolved critical or high-severity defect
* Restore rehearsal succeeds
* Pilot data reconciles
* Release approval is recorded

# 7. Vertical-Slice Rule

Each implementation stage must deliver usable vertical slices where practical.

A vertical slice includes:

```text
data
→ backend business workflow
→ authorization
→ API contract
→ frontend workflow
→ audit
→ tests
```

Do not mark a business feature complete when only its UI, route, schema, or controller exists.
