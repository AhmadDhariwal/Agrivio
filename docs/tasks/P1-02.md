The PRD defines:

* What Agrivio is
* Who it serves
* Which problems it solves
* What Release 1 must deliver
* Which functional and non-functional requirements apply

### 4. Product Goals

### 13. Business Invariants

State the required invariants at a product level:

```text
Current warehouse stock must reconcile with valid stock movements.

Customer receivable must reconcile with opening balance, credit sales, returns, allocated payments, and credits.

Supplier payable must reconcile with opening payable, credit purchases, purchase returns, payments, and supplier credits.

Cash and bank balances must reconcile with opening balances, inflows, outflows, and transfers.

Posted financial and stock transactions must not be permanently deleted.

Cross-organization data access must never be permitted.
```

# Deliverable 2 — `docs/RELEASE_1_SCOPE.md`

Define the binding Release 1 boundary.

State that Release 1 is a production-ready cloud-first web release for the first two clients and future multi-tenant onboarding.

---

### 3. Explicitly Excluded

Include every deferred item from `PROJECT_DECISIONS.md`.

Explain that “architecture-compatible” does not mean “implemented in Release 1.”

---

### 4. Release Boundaries

Clarify:

* Cloud-first, not offline-first
* Web application, not native mobile
* Accounting-lite, not full general ledger accounting
* Manual subscription billing, not automated recurring billing
* Fixed reports, not a custom report builder
* Browser printing, not silent native printer control
* English interface, not full Urdu localization
* Shared SaaS and dedicated-cloud compatible, not self-service on-premise

---

### 5. Scope-Change Policy

A proposed feature is a Release 1 scope change when it:

* Introduces a new module
* Changes a finalized business invariant
* Requires new external integrations
* Adds a new deployment model
* Adds full accounting capability
* Changes tenant-isolation strategy
* Adds offline synchronization
* Changes subscription enforcement
* Materially changes the data model after freeze

Every scope change must document:

* Business reason
* Client requesting it
* Urgency
* Architecture impact
* Data-model impact
* Test impact
* Schedule impact
* Whether another Release 1 feature will be removed

No agent may approve scope changes.

---

### 6. Release Completion Criteria

Release 1 is complete only when:

* Required workflows operate end to end
* Tenant-isolation tests pass
* Permission tests pass
* Stock reconciliation passes
* Customer and supplier ledger reconciliation passes
* Cash and bank reconciliation passes
* Weighted-average costing tests pass
* Required reports reconcile
* Printing formats are verified
* Excel import is verified
* Backups and restore procedures are tested
* UAT is approved by initial clients
* No critical known defect remains
* Required documentation is current

---
